# 인용 데이터 설계

이 문서는 인용 기반 연결·추천([제품 비전](../ProductVision.md#6-인용-기반-연결추천))이 쓰는 인용 데이터를 OpenAlex에서 어디까지 가져와 어떻게 저장하는지 정한다. 가져오는 양은 사용자 설정으로 조절한다([사용자 설정 설계](Settings.md)). 거리 점수의 계산식과 화면은 M3-T4~T7에서 정한다. 전체 문서 목록은 [문서 인덱스](../index.md)에서 확인한다.

## 1. OpenAlex 조사

2026-11-15에 OpenAlex API를 직접 불러 확인한 내용이다.

| 요청 | 형태 | 비용 |
| --- | --- | --- |
| 논문 한 편 | `GET /works/doi:<DOI>` 또는 `GET /works/W<번호>` | 무료 |
| 목록 | `GET /works?filter=...&per-page=200` | 요청당 0.0001달러(쪽당 200건까지 같은 값) |

- 하루 예산은 키가 없으면 같은 IP가 함께 쓰는 0.1달러, 무료 키가 있으면 키마다 1달러다. 응답 헤더 `X-RateLimit-Remaining-USD`에 남은 예산이 온다. Render 서버는 IP를 다른 서비스와 함께 쓰므로 배포 환경에서는 `OPENALEX_API_KEY`를 넣는다([논문 검색 설계](PaperSearch.md#1-검색원)).
- 논문 한 편 응답의 `referenced_works`가 참고문헌 OpenAlex ID 목록이다.
- 피인용은 `filter=cites:W<번호>`로 찾는다. `from_publication_date:<날짜>`로 기간을, `sort=publication_date:desc`로 최신 순을 정한다. `select=id,publication_date,referenced_works`로 인용한 논문의 참고문헌까지 한 번에 받는다.
- 예: 'Attention Is All You Need'(W2626778328)는 피인용이 136,382건이고, 그중 최근 1년 안의 것이 15,291건이었다. 전부 가져오는 것은 비용과 저장 크기 모두 맞지 않는다.
- 여러 논문의 제목 등은 `filter=openalex_id:W1|W2|...`로 한 번에 100건까지 받는다.

## 2. 서재 논문과 OpenAlex 연결

- 논문에 `openalex_id`(예: `W2626778328`, 없으면 비어 있음)를 더한다. 마이그레이션 0003이 열을 만든다([서재 데이터 설계의 스키마 변경](Library.md#3-스키마-변경)).
- OpenAlex 검색 결과에서 추가한 논문은 결과의 ID를 그대로 넣는다.
- 그 밖의 논문(arXiv 검색 결과, 이미 서재에 있는 논문)은 DOI로 `GET /works/doi:<DOI>`를 불러 찾는다. arXiv 논문은 DOI가 없으면 `10.48550/arXiv.<arXiv ID>`를 DOI로 쓴다. 찾지 못하면 비워 두고, 인용 기능에서 "OpenAlex에서 찾지 못함"으로 보인다. 제목으로 찾는 것은 다른 논문과 잘못 이어질 수 있어 하지 않는다.

## 3. 가져오는 범위

서재 논문 A마다 다음을 가져온다.

- **참고문헌**: A의 `referenced_works` 전부. 논문 한 편 요청 한 번(무료)이다.
- **피인용**: A를 인용한 논문 가운데 **오늘부터 1년 안에 출판된 것만**, 최신 순으로 **최대 N건**을 가져온다. 오래된 피인용은 가져오지 않는다. 사용자가 정했다. 최근 연구 흐름에서 A가 어떻게 쓰이는지가 추천에 필요한 정보이고, 1년 안으로 줄여도 많이 인용된 논문은 수천~수만 건이기 때문이다.
  - N은 사용자 설정 `citing_limit`이다. 기본값은 200(목록 요청 한 번)이고, 1~1000 사이로 바꿀 수 있다. 요청 수는 N/200을 올림한 값이다.
  - 피인용 논문의 출판일과 참고문헌을 함께 받는다. 공동 인용(A와 함께 인용된 논문)과 서지 결합(A와 참고문헌을 공유하는 논문)을 이 범위 안에서 계산하기 위해서다.
- 1년은 가져오는 날을 기준으로 한다. 기준 날짜를 저장해, 나중에 다시 가져올 때 범위가 바뀐 것을 알 수 있게 한다.

## 4. 저장

- 인용 데이터는 서재 파일과 **다른 파일 `citations.db`**(SQLite)에 둔다. 위치는 서재 파일과 같은 데이터 폴더다.
  - 서재 파일은 고칠 때마다 드라이브에 통째로 올라간다([구글 드라이브 동기화 설계](DriveSync.md#5-동기화)). 인용 데이터는 서재보다 훨씬 크고 OpenAlex에서 다시 받을 수 있으므로, 함께 두면 올리기만 무거워진다.
  - 서버는 재시작 때 디스크가 지워진다. 그때마다 모든 논문의 인용을 다시 받으면 OpenAlex 예산을 쓰므로, `citations.db`도 드라이브 `Jjabtero` 폴더에 올린다. 다만 다시 받을 수 있는 캐시라 충돌을 따지지 않는다. 인용 데이터를 가져온 뒤에 올리고, 시작할 때 로컬에 없으면 받는다. 세부 동작은 M3-T3에서 정한다.
- 저장하는 것(A는 서재 논문의 OpenAlex ID):

| 표 | 내용 |
| --- | --- |
| `fetches` | A마다 가져온 시각, 피인용 기간의 시작 날짜, 그때의 `citing_limit`, 1년 안 피인용 전체 건수 |
| `references` | A → A가 인용한 논문 |
| `citations` | A를 인용한 논문 → A, 그 논문의 출판일, A와 공유하는 참고문헌 수(서지 결합) |
| `cocitations` | A와 함께 인용된 논문, 함께 인용된 횟수. 2회 이상인 것 가운데 많은 순으로 A마다 최대 100건 |
| `works` | 화면에 보일 논문의 제목, 저자, 연도, 게재처, DOI, 피인용 수. 보여 줄 때 없으면 받아 둔다 |

- 피인용 논문의 참고문헌 목록 자체는 저장하지 않는다. N=200이면 A마다 1만 건쯤이 되어 파일이 커지기 때문이다. 가져올 때 서지 결합과 공동 인용 수로 줄여 저장한다.
- 서재 논문을 지우면 그 논문의 인용 데이터도 지운다. `works`는 다른 곳에서 쓰지 않으면 지운다.

## 5. 갱신

- 논문을 서재에 넣으면 그 논문의 인용 데이터를 가져온다.
- 가져온 지 7일이 지난 논문은 다시 가져온다. 1년 기간이 앞으로 움직이고 새 피인용이 생기기 때문이다.
- `citing_limit`을 바꾸면, 다음에 가져올 때 새 값을 쓴다. 바로 다시 받고 싶으면 설정 화면에서 "인용 데이터 새로 받기"를 누른다.
- OpenAlex 예산이 다 떨어지면(응답 429) 멈추고 다음 갱신 때 이어서 한다.
- 실행 방식(백그라운드 작업, 한 번에 처리하는 논문 수)은 M3-T3에서 정한다.

## 6. 미결정 사항

- 거리 점수 계산식(직접 인용, 서지 결합, 공동 인용의 가중치): M3-T5.
- 서재 밖 추천 점수: M3-T6.
