이 문서는 닫힌 마일스톤 M7 태그의 완료 기록과, 그동안 끝난 이슈의 완료 기록을 보관한다. 기록 형식과 순서는 [완료](Done.md)와 같으며, 진행 중인 마일스톤의 기록은 완료 문서에 있다.

## M7-T3 태그별 인용 그래프

- 시작일: 2026-11-16
- 완료일: 2026-11-16
- 근거 문서: [태그 설계](design/Tags.md#5-태그별-그래프)
- 참고 자료: 없음

### 계획
- 그래프 API가 태그를 받아 그 태그를 모두 가진 서재 논문만으로 그래프와 추천을 계산하게 한다.
- 그래프 화면이 왼쪽에서 고른 태그를 쓰고, 그래프 화면에서 태그를 누르면 그래프를 다시 그리게 한다.
- 테스트를 더하고 브라우저에서 확인한다.

### 진행 기록
- 2026-11-16: 병합되지 않은 가장 최근 브랜치 `m7-t2-tag-editing`에서 작업 브랜치를 만들었다.
- 2026-11-16: 그래프 API에 `tags`를 더하고, 그래프 화면이 왼쪽에서 고른 태그를 쓰게 했다. 그래프 화면에서 왼쪽 태그를 누르면 그래프에 머문다. 서버 테스트 1개, 화면 상태 테스트 1개를 더했다.
- 2026-11-16: 시연 서버에서 브라우저로 확인했다. 전체 9편·인용 선 10개에서 `language`를 고르자 2편·인용 선 1개로 다시 그렸고, 칩을 지우자 9편으로 돌아왔다. 안내 문구의 두 문장 사이 빈칸이 빠진 것을 고쳤다.
- 2026-11-16: M7의 태스크가 모두 끝나 M7 기록과 완료 문서의 이슈 기록을 `docs/Done-M7.md`로 옮겼다.

### 결정 사항
- 태그로 거른 그래프의 추천에서도 서재 전체를 뺀다. 고른 태그가 없는 서재 논문이 추천에 나오면 이미 가진 논문을 다시 권하는 셈이기 때문이다.

## M7-T2 논문 상세·서재 목록의 태그 붙이기·떼기와 왼쪽 태그 목록의 이름 바꾸기·지우기

- 시작일: 2026-11-16
- 완료일: 2026-11-16
- 근거 문서: [태그 설계](design/Tags.md#3-api)
- 참고 자료: 없음

### 계획
- 태그 API 네 개(논문 태그 바꾸기, 여러 편에 붙이기·떼기, 이름 바꾸기·합치기, 지우기)를 만든다.
- 논문 상세의 태그 칩과 자동 완성 입력, 서재 목록의 여러 편 고르기와 태그 붙이기·떼기, 왼쪽 태그 메뉴를 만든다.
- 테스트를 더하고 브라우저에서 확인한다.

### 진행 기록
- 2026-11-16: 병합되지 않은 가장 최근 브랜치 `m7-t1-tags-design`에서 작업 브랜치를 만들었다. `tags` 모듈과 API를 만들어 앱에 등록했다.
- 2026-11-16: 문서 연결 검사가 실패했다. 설계 문서의 절 제목에 태스크 표시("(M7-T2)")를 붙여 코드가 가리키는 앵커(`#3-api`)와 맞지 않았고, 새 코드를 문서에서 링크하지 않았다. 절 제목에서 태스크 표시를 빼고 코드 링크를 더했다.
- 2026-11-16: API 테스트 5개, 서재 상태 테스트 4개를 더했다. 화면(논문 상세의 태그 칩과 입력, 서재 목록의 고르기와 태그 막대, 왼쪽 태그 메뉴와 대화 상자)을 만들었다.
- 2026-11-16: 시연 서버에서 브라우저로 확인했다. 'Attention'에 `transformer`를 붙이자 칩과 왼쪽 목록에 나왔고, 두 편을 골라 `nlp`를 붙이자 왼쪽 목록이 `nlp 2`가 되었다. 메뉴로 `nlp`를 `language`로 바꾸고 `transformer`를 지웠으며, `language`를 누르자 서재 목록이 2편으로 걸러졌다. 브라우저 콘솔 오류는 없었다.

### 결정 사항
- 자동 완성은 브라우저 기본 `datalist`로 한다. 기존 태그 이름을 보여 주기에 충분하고 부품을 더 들이지 않아도 되기 때문이다.
- 여러 편 고르기는 표의 행 고르기(상세 열기)와 따로 둔다. 행을 누르면 지금처럼 상세가 열리고, 체크 상자만 여러 편 고르기다.

## M7-T1 태그 설계(태그 이름 규칙, 붙이기·떼기·이름 바꾸기·지우기 API, 화면, 태그별 그래프)

- 시작일: 2026-11-16
- 완료일: 2026-11-16
- 근거 문서: [태그 설계](design/Tags.md)
- 참고 자료: 없음

### 계획
- 지금 있는 태그 기능을 확인하고, 태그 붙이기·떼기, 이름 바꾸기·지우기, 태그별 그래프를 설계한다.
- 로드맵에 M7을 더한다.

### 진행 기록
- 2026-11-16: 사용자가 태그 달기부터 하자고 했다. 태그를 붙이면 태그별 그래프와 서재에서 고른 태그만 보기가 된다는 것이다. 병합되지 않은 가장 최근 브랜치 `i22-note-box-size`에서 작업 브랜치를 만들었다.
- 2026-11-16: 지금 기능을 확인했다. 태그 표와 왼쪽 태그 필터(고른 태그를 모두 가진 논문만)는 있고, 태그는 검색에서 담을 때만 붙일 수 있었다. 서재 논문의 태그를 바꾸는 API·화면, 태그 이름 바꾸기·지우기, 그래프의 태그 거르기는 없었다.
- 2026-11-16: 태그 설계 문서를 쓰고 로드맵에 M7(T1~T3)과 문서 인덱스를 더했다.

### 결정 사항
- 서재에서 고른 태그만 보기는 이미 있으므로 그대로 쓰고, 그래프도 같은 태그 선택을 쓴다. 서재와 그래프가 같은 선택을 보여야 헷갈리지 않기 때문이다.
- 여러 논문에 한 번에 태그를 붙이는 기능을 넣는다. 이미 담아 둔 논문들에 태그를 붙이려면 한 편씩은 번거롭기 때문이다.
- 쓰지 않는 태그는 지운다. 태그를 붙이고 떼면 논문의 `updated_at`을 바꿔 드라이브 자동 합치기와 맞춘다.

## I22 리더 메모 상자: 기본 너비 1.5배, 아래로 화면을 넘지 않게, 긴 내용은 상자 안에서 스크롤

- 시작일: 2026-11-15
- 완료일: 2026-11-15
- 근거 문서: [PDF 리더 설계](design/Reader.md#6-화면)
- 참고 자료: 없음

### 계획
- 메모 상자(하이라이트 메모, 영역 메모)의 너비를 288px에서 432px로 늘린다.
- 상자 아래 끝이 리더 화면 아래를 넘지 않게 최대 높이를 정하고, 긴 메모는 상자 안에서 스크롤되게 한다. 아래 공간이 좁으면 상자를 올린다.
- 위치 계산을 순수 함수로 두고 테스트하며, 브라우저에서 확인한다.

### 진행 기록
- 2026-11-15: M6-T4 작업 중에 사용자가 요청했다. M6-T4를 마친 뒤 병합되지 않은 가장 최근 브랜치 `m6-t4-text-citations`에서 작업 브랜치를 만들었다.
- 2026-11-15: 위치 계산 `notePlacement`와 보이는 영역 재기를 더하고, 두 메모 상자의 너비·최대 높이·안쪽 스크롤을 바꿨다. 상자의 라벨과 버튼 줄은 줄어들지 않게 했다.
- 2026-11-15: 브라우저에서 확인했다. 줄 40개짜리 메모로 상자 너비 432px, 아래 끝 892px(리더 화면 아래 900px), 메모 칸 안 스크롤, 버튼 보임을 확인했다. 리더를 위로 스크롤해 하이라이트를 화면 아래로 보내 보려 했으나 이미 맨 위에 가까워 79px만 움직여, 창 높이를 420px로 줄여 확인했다. 상자가 200px(212~412)를 확보하도록 위로 올라갔고 아래 끝은 화면 안이었다.

### 결정 사항
- 상자는 리더 화면 안에 두되 최소 200px는 확보한다. 그보다 작으면 메모 칸과 버튼이 함께 보이지 않기 때문이다.
- 스크롤은 상자 전체가 아니라 메모 칸에서 한다. 저장·닫기 버튼을 찾으러 스크롤하지 않게 하기 위해서다.
