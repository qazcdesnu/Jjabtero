## M1-T9 구글 드라이브 Jjabtero 폴더와 서재 동기화(Drive API) 조사와 구현

- 시작일: 2026-11-01
- 근거 문서: [제품 비전](ProductVision.md#3-핵심-요구사항), [서재 데이터 설계](design/Library.md#2-데이터베이스-파일과-연결), [시스템 구조](Architecture.md#1-실행-형태)

### 계획
- 비밀 값과 서재 데이터가 커밋되지 않도록 `.gitignore`를 보강한다.
- OAuth 인증, Drive API 파일 다루기, 토큰 만료, 충돌 감지 방법을 조사해 정리한다.
- 동기화 시점과 충돌 처리 방식을 사용자와 정하고, 설계 문서를 쓴다.
- 인증, 동기화, API, 화면을 구현하고 테스트한다. 실제 드라이브로 확인한다.

### 진행 기록
- 2026-11-01: 사용자가 Jjabtero 전용 Google Cloud 프로젝트를 개인 계정으로 만들었다. 학교 계정은 "조직 없음" 위치에 프로젝트를 만들 권한이 없었다. 대조군 앱의 OAuth 클라이언트를 같이 쓰는 안은 드라이브 파일과 설정이 섞일 수 있어 쓰지 않았다.
- 2026-11-01: 사용자가 웹 애플리케이션 OAuth 클라이언트(리디렉션 URI `http://127.0.0.1:8000/api/drive/callback`, `http://localhost:8000/api/drive/callback`, 범위 `drive.file`, 테스트 사용자 개인 계정)를 만들고 JSON을 `reference/`에 넣었다. 저장소가 공개이고 아직 커밋되지 않은 상태여서, 파일을 `~/Library/Application Support/Jjabtero/google_client_secret.json`(권한 600)으로 옮기고 빈 `reference/`를 지웠다. 보안 비밀은 출력하지 않았다.
- 2026-11-01: 작업을 시작했다. PR #14, #15가 병합되지 않아 `m1-t7-reading-notes` 위에 작업 브랜치를 만들었다. 사용자가 ProjInit에 비밀 값 전용 경로를 요청했고, 그 전까지는 사용자 데이터 폴더에 두고 진행하라고 했다.
- 2026-11-01: `.gitignore`에 `client_secret*.json`, `*token*.json`, `*.db`, `.DS_Store`를 더했다.
- 2026-11-01: 공식 문서를 조사했다. 테스트 상태의 갱신 토큰은 7일 뒤 만료되고, 프로덕션으로 게시하면 없어진다. 민감하지 않은 범위만 쓰면 검수 없이 게시해도 경고가 없다. Drive API의 `files.update`에는 덮어쓰기를 막는 조건부 요청이 문서에 없어, 올리기 직전에 `version`을 다시 읽어 충돌을 감지하기로 했다. `drive.file` 권한이 프로젝트 단위인지 클라이언트 단위인지는 문서에서 확인하지 못했고, 전용 프로젝트를 써서 상관이 없어졌다.
- 2026-11-01: 동기화 시점(자동 + 수동 단추), 충돌 처리(물어보고 버린 쪽 백업), 토큰 만료(프로덕션 게시)를 물었고 사용자는 셋 다 추천안을 골랐다.
- 2026-11-01: 구글 드라이브 동기화 설계를 쓰고 인덱스에 링크했다. 동기화 상태와 백업은 데이터베이스 옆에, 클라이언트와 토큰은 사용자 데이터 폴더에 두기로 설계를 고쳤다. `JJABTERO_DB`로 다른 데이터베이스를 쓸 때 상태가 섞이지 않게 하기 위해서다. 서재 데이터 설계와 시스템 구조를 맞췄다.
- 2026-11-01: `google_auth`, `drive`, `drive_sync`, `drive_api` 모듈을 만들고 앱과 논문 API(넣기·고치기·지우기 뒤 자동 올리기 예약)에 연결했다. 모든 테스트가 실제 사용자 데이터를 건드리지 않도록 `tests/conftest.py`에서 사용자 데이터 폴더와 데이터베이스 경로를 임시 폴더로 바꾼다. 백엔드 테스트는 111개다.
- 2026-11-01: 프론트엔드에 드라이브 API 함수, `driveState.ts`(주기적 상태 불러오기, `data_version` 콜백), 머리줄 `DriveStatus.vue`(연결, 상태, 메뉴, 충돌 대화 상자)를 더했다. 프론트엔드 테스트는 55개다. 일괄 검사를 모두 통과했다.

### 결정 사항
- 비밀 값(OAuth 클라이언트 JSON, 토큰)은 저장소 밖 사용자 데이터 폴더에 둔다. ProjInit에 비밀 값 경로 규칙이 생기면 그에 맞춘다.
- 동기화는 앱 시작 때 한 번, 논문을 바꾼 뒤 5초 동안 더 바뀌지 않으면 자동으로, 그리고 수동 단추로 한다. 사용자가 골랐다.
- 충돌이면 자동 동기화를 멈추고 사용자가 쓸 쪽을 고르며, 버린 쪽은 백업한다. 사용자가 골랐다.
- 동의 화면은 프로덕션으로 게시한다. 사용자가 골랐다.
- 파일 전체를 받고 올린다. 서재가 작아 행 단위 동기화보다 단순하고 안전하기 때문이다. 로컬 변경은 파일 바이트가 아니라 SQL 덤프 해시로 판단한다.
- Google 클라이언트 라이브러리 대신 httpx2로 OAuth와 Drive API를 직접 부른다. 쓰는 요청이 적고 가짜 응답으로 테스트하기 쉽기 때문이다.
